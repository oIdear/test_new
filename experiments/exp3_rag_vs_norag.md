# 实验三：RAG 增强 vs 无 RAG（多告警多指标评估）

**日期：** 2026-05-22  
**测试集：** 10 条真实告警（a2×3, a1×3, a3×2, a4×2）  
**LLM：** DeepSeek-Reasoner（temperature=0.3）  
**RAG 配置：** bge-base-en-v1.5 + BM25+向量+RRF+MMR，top-k=3

---

## 1. 评估指标定义

| 指标 | 说明 | 提取方式 |
|---|---|---|
| 来源引用数 | 报告中 `[来源:xxx]` 格式的出现次数 | 正则匹配 |
| RFC 引用数 | 报告中出现的不同 RFC 标准号数量 | 正则匹配 + 去重 |
| 异常类型识别 | 报告是否命中告警对应 pattern 的关键词 | 关键词匹配 |
| 验证建议条数 | 【6】验证建议节中可执行步骤数 | 节内列表项计数 |

## 5. 关键发现

| 发现 | 说明 |
|---|---|
| 来源引用：无RAG必然为 0 | 无 RAG 时 LLM 无法输出 `[来源:xxx]` 格式引用，有 RAG 时平均 5.4 条 |
| RFC 引用更精确 | 有 RAG 时平均引用 1.2 个 RFC，无 RAG 时 0.3 个，RAG 引用来自检索到的具体文档 |
| 异常类型识别率 | 有 RAG 100.0%，无 RAG 100.0%；RAG 提供了 pattern 分类的外部依据 |
| 验证建议：有RAG更聚焦 | 有 RAG 时平均 6.2 条，无 RAG 时 8.9 条；无 RAG 倾向产生大量泛化建议（如 gid=153 达 14 条），有 RAG 的建议更少但均附带证据来源，针对性更强 |
| RAG 的不可替代价值 | 无 RAG 时 LLM 无法引用 Prefix-Anomaly.csv 中的历史案例，该私有数据不在 LLM 训练集中；有 RAG 时可将历史攻击者 AS 案例纳入证据链 |
| 结论可溯源性 | RAG 平均提供 5.4 条来源标注，使每条推论均可追溯至具体 RFC 或论文，满足学术论文引用规范 |
