# 第七章 实验结果与评估

**数据生成日期：** 2026-05-22  
**测试数据集：** `alarms_wide_202408.jsonl`（2024年8月真实 BGP 告警，RouteViews wide collector）  
**实验脚本目录：** `rag_system/exp1~5_*.py`，结果目录：`experiments/`

## 7.1 实验概述

本章通过五组实验对基于 RAG 的 BGP 异常溯源分析系统进行全面评估，重点验证 RAG 组件的有效性、各技术模块的必要性以及系统的整体工程性能。测试集为 20 条来自真实网络环境的 BGP 异常告警，覆盖四种主要异常类型（a1/a2/a3/a4），与系统设计的检测目标一致。

| 实验 | 核心问题 | 测试规模 |
|---|---|---|
| 实验一：检索性能评估 | RAG 能否为各类型告警检索到相关知识？ | 20 条告警 |
| 实验二：消融实验 | 每个技术组件是否必要？去掉任一是否会导致性能下降？ | 20 条告警 × 4 配置 |
| 实验三：RAG vs 无 RAG | RAG 是否显著提升 LLM 溯源分析质量？ | 10 条告警 × 2 配置 |
| 实验四：系统效率 | 检索延迟是否满足实时交互需求？RAG 是否增加额外开销？ | 20 条告警 + 10 条端到端 |
| 实验五：历史案例匹配 | 私有历史异常案例库能否有效覆盖真实告警？ | 20 条告警 |

**四种异常类型说明：**

| 类型 | 含义 | 样本数 |
|---|---|---|
| a1 | RPKI/IRR Origin 验证异常 | 6 |
| a2 | Valley-free 破坏 / 路由泄露 | 7 |
| a3 | 保留/未知 ASN 出现在 AS 路径中 | 5 |
| a4 | 同源组织 origin AS 变更 | 2 |
| **合计** | — | **20** |

|---|---|---|---|

### 7.4.6 C2 在 a2 类型上退化的原因分析

C2 直接对含 AS 路径字符串（如 `"3257 1299 6939 ..."`）的告警原始字段进行 BM25 检索时，大量 AS 号数字 token 获得高 BM25 分数，将检索结果拉向含 AS 号记录的 CSV 文件，而非 RFC 文档中的 valley-free 内容。这一现象揭示了 **BGP 告警数据对混合检索的独特挑战**：结构化网络数据中的数值标识符（AS 号、IP 前缀）会污染词汇检索信号，必须在查询阶段进行语义转换。只有先通过 Pattern 语义映射去除数值噪声，bge 模型的高维语义表示和 BM25 的词汇匹配才能协同发挥作用。

### 7.4.7 关键结论

- 完整系统 C3 相比基线 C0 召回率提升 **+75pp**（20%→95%），验证了整体方案的有效性。
- **C1 反而劣于 C0**（-10pp）：单独更换嵌入模型在原始告警字段噪声下不能发挥优势，说明模型升级必须配合查询词优化。
- **a2 类型（路由泄露）从 0% 提升到 100%** 是最关键突破：C0/C1/C2 均对 a2 完全无效，只有 C3 的 Pattern 语义映射（将 "a2" 代码转为 "valley-free violation route leak provider customer peer" 描述）才触发正确检索。
- **BGP 告警数据的独特挑战**：AS 路径字符串中的大量数值 token 会污染 BM25 词汇匹配信号，必须在查询阶段进行语义转换，三个组件**缺一不可**。

### 7.5.5 关键结论

- **来源引用：** 无 RAG 时 LLM 无法输出任何 `[来源:xxx]` 格式引用（0 条）；有 RAG 时平均 **5.4 条**，每条推论均可追溯至具体 RFC 或论文，满足学术论文引用规范。
- **RFC 引用精确性：** 有 RAG 时平均引用 1.2 个 RFC 编号，无 RAG 时仅 0.3 个；有 RAG 的引用来自检索到的真实文档，而非 LLM 凭记忆生成（后者错误风险高）。
- **分析聚焦性：** 有 RAG 时平均验证建议 6.2 条，无 RAG 时 8.9 条；无 RAG 倾向产生大量泛化建议（如 gid=153 达 14 条），有 RAG 的建议更少但均附带证据来源，**针对性更强**。
- **私有知识不可替代：** 无 RAG 时 LLM 无法利用 Prefix-Anomaly.csv 中的历史攻击者 AS 案例——该私有数据不在 LLM 训练集中，只有通过 RAG 注入才能纳入证据链。
- 异常类型识别率两者均达 100%，说明 RAG 的价值体现在**结论的可信度与可溯源性**，而非基本判断能力。

### 7.7.6 关键结论

- 私有历史案例库对全部 20 条测试告警覆盖率达 **100%**，平均每条告警命中 10.3 个历史案例，验证了案例库的实用价值。
- 三类案例库形成互补：路径异常库（96 次命中）和前缀劫持库（90 次命中）是主力，路由泄露库专门为 a2 类型提供额外溯源依据（a2 命中路由泄露 13 次，其他类型合计 7 次）。
- 历史案例数据属于**私有运营知识**，LLM 训练数据中不包含，只有通过案例库注入才能利用——这一点是语义向量检索无法替代的。
- 语义检索与精确匹配形成**双通道互补**：语义检索召回 RFC 规范和研究论文（提供理论依据），精确匹配提供具体历史事件（提供案例佐证），双路注入使分析既有规范支撑又有案例证明。

### 7.8.2 RAG 系统有效性的多维证明

本章实验从五个维度共同证明 RAG 组件有效：

1. **知识覆盖充分（实验一）：** 100% 的真实告警能从知识库中检索到相关内容，四种异常类型均无遗漏，证明知识库与检测目标高度匹配。

2. **组件设计必要（实验二）：** 基线方法召回率仅 20%，完整系统达 95%，提升 75pp。特别是 a2 类型路由泄露在未使用 Pattern 语义映射时召回率为 0，证明针对 BGP 告警数值噪声的查询词去噪设计是系统有效性的关键。

3. **输出质量提升（实验三）：** 有 RAG 时来源引用从 0 提升至平均 5.4 条，分析报告从"无依据的推断"转变为"有来源标注的证据链推理"，同时 RFC 引用更精确，建议更聚焦。

4. **工程代价极低（实验四）：** 检索延迟仅 37ms，占端到端时间 0.1%，有 RAG 的端到端时间（53.5s）反而略短于无 RAG（55.5s），证明 RAG 引入了零额外工程负担。

5. **私有知识不可替代（实验五）：** 历史案例库精确匹配 100% 覆盖所有告警，且此类私有运营知识在 LLM 训练集中不存在，RAG 是利用它的唯一通道。
