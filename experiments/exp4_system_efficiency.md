**日期：** 2026-05-22  
**测试集：** 20 条真实告警（检索延迟）；10 条告警（端到端时间，来自实验三）  
**检索配置：** bge-base-en-v1.5 + BM25+向量+RRF+MMR，Top-3

## 3. 检索延迟（Retrieval Latency）

测量 20 条真实告警的 Top-3 混合检索（BM25+向量+RRF+MMR）耗时：

| 指标 | 值 |
|---|---|
| 平均检索延迟 | **37.3 ms** |
| 中位数（P50） | 33.3 ms |
| P95 | 66.6 ms |
| 最大值 | 76.2 ms |
| 平均 Top-1 RRF融合分数 | 0.0313 |

**检索延迟分布：**

| 延迟区间 | 查询数 |
|---|---|
| < 100ms | 20 |
| 100~200ms | 0 |
| 200~500ms | 0 |
| 500ms~1s | 0 |
| > 1s | 0 |

---

## 4. 端到端报告生成时间

说明：端到端时间 = 检索延迟 + LLM 推理时间，主要由 LLM API 响应决定。

| 指标 | 有 RAG（秒） | 无 RAG（秒） |
|---|---|---|
| 平均 | 53.51 | 55.47 |
| 中位数 | 56.20 | 58.20 |
| 最短 | 37.48 | 40.03 |
| 最长 | 62.18 | 68.57 |

> **注：** 检索延迟（平均 37ms）占端到端时间 0.1%，LLM 推理占 99.9%，系统瓶颈在 LLM API。

---

## 5. 关键发现

| 发现 | 说明 |
|---|---|
| 检索速度快 | 平均检索延迟 37ms，满足实时交互需求 |
| LLM 是系统瓶颈 | 检索占端到端时间 0.1%，提速应优先优化 LLM 调用 |
| RAG 不显著增加生成时间 | 有 RAG 53.5s vs 无 RAG 55.5s，增加检索的代价可忽略 |
| 索引加载为一次性开销 | 5.2s 仅在服务启动时发生，运行期无延迟 |
