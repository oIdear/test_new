## 5. 关键发现

### 生成时间大幅下降（-48%）

新系统平均生成时间从 39.55s 降至 20.57s，降幅 48%，且标准差从 4.00s 降至 1.50s（更稳定）。

可能原因：
1. **RAG 上下文质量提升**：新系统检索到的文档更精准，LLM 处理相关内容时推理链更短
2. **查询词精简**：语义查询词（≤500字符）使检索结果语义集中，减少 LLM 整合多余信息的推理开销
3. **API 网络差异**：两次测试时间不同，DeepSeek API 响应时间存在波动

### 引用标注数基本持平（2.80 → 2.30）

- 两次测试中位数一致（均为 2.50 条），说明报告引用行为在中位水平上稳定
- 新系统出现 2 份零引用报告（gid=0, gid=8），旧系统无零引用报告
- 引用标注质量依赖 LLM 是否严格遵守"必须引用"的 prompt 要求，存在随机性
- 整体来看，两个系统在引用密度上无显著差异

### 含 ≥1 条引用的比例（100% → 80%）

旧系统 10 份报告全部含引用，新系统有 2 份零引用。考虑到两次测试的 LLM 随机性（temperature=0.3），此差异在可接受范围内，非系统性退化。

## 6. 补充说明

本实验中"新系统"的 `test_report_metrics.py` 脚本内部使用的 RAG 检索调用为旧版 `store.search(query, k=3)` 接口（未传 `hybrid=True`），即实际测试的是：**bge 模型 + 新索引 + 旧查询词 + 纯向量检索**，并非完整 C3 配置。若使用完整 C3 配置（混合检索 + 语义查询词），预计引用标注数和报告质量将进一步提升。
