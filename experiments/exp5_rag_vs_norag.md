## 4. 典型段落对比

### 无RAG 的关键证据链（摘录）

> "事件1 `non_valley_free_2` 编码为 `1 0 -1 1 x x -1 -1`：路径 `6453 23752 23764 24115 9498` 中，`23764` 与 `24115` 之间为 `-1→1`（即下游→上游）随后 `24115→9498` 又为 `1→-1`（上游→下游），构成 valley-free 违反 → 路由泄露"

**特点：** 完全依赖告警内字段自推理，无外部知识支撑，推理细节丰富但无法被独立验证。

### 有RAG 的关键证据链（摘录）

> "异常数据中 `patterns.a2` 和 `a3` 包含 `non_valley_free` 标记，以及 `none_rel` 标记（AS 关系未知）。检索上下文 **[2402.16025v1.pdf]** 明确指出 P2 (Route Leak) 定义为 valley-free 违反。推论：路由通告违反了互联网基本路由策略，构成路由泄露。"

**特点：** 将告警字段与 BEAM 论文中的 P2/P3 模式定义对应，推论有文献依据，可引用至论文。

## 5. 关键发现

| 发现 | 说明 |
|---|---|
| 有无RAG均能完成基础分析 | valley-free 违规、culprit AS 识别、置信度评估两者均能完成，体现LLM内在BGP知识 |
| 有RAG使分析粒度更细 | 识别出 P2（路由泄露）和 P3（路径操纵）两类而非单一类型，与论文中的异常分类体系对齐 |
| 有RAG显著提升可溯源性 | 引用 2402论文 P2/P3 定义，使分析结论有外部文献支撑，适合论文写作中的案例引用 |
| 有RAG的验证建议更具体 | 新增数据平面验证（RIPE Atlas 探测）建议，在无RAG版本中未出现 |
| 两版报告置信度相同（0.85） | LLM 对自身判断的不确定性估计不受RAG影响，验证了模型的自洽性 |
| 无RAG版本主动承认局限性 | 无RAG报告中出现"缺少 RAG 上下文"的表述，证明LLM能识别自身知识不足 |
